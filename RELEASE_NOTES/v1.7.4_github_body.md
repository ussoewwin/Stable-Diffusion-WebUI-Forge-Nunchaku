# Pony SDXL LoRA — CLIP Key Mapping Fix

**Scope:** Pony / SDXL LoRAs on IntegratedCLIP (Transformers 5.6+).  
**Change:** `model_lora_keys_clip()` in `modules_forge/packages/comfy/lora.py` now maps `lora_te1_*` to both `transformer.text_model.encoder.layers.*` and `transformer.encoder.layers.*`.

---

## Summary

- **Problem:** IntegratedCLIP uses `clip_l.transformer.encoder.layers.*` without a `text_model` segment. Legacy mapping only looked for `text_model.encoder.layers.*`, so CLIP-L LoRA keys (`lora_te1_*`) did not bind.
- **Symptom:** UNet-only LoRA effect, weak/no prompt LoRA, or `[LORA] LoRA mismatch for CLIP` when >50% of keys fail to match (`networks.py`).
- **Fix:** Dual `clip_layer_paths` lookup in `model_lora_keys_clip()` (merged via `08e6e70`, PR #1 `3a8ea0c`).

Full write-up: [`docs/Pony_SDXL_LoRA_CLIP_Fix.md`](https://github.com/ussoewwin/Stable-Diffusion-WebUI-Forge-Nunchaku/blob/main/docs/Pony_SDXL_LoRA_CLIP_Fix.md)
