# Hires Fix 5D Tensor Compatibility Patch Explanation

## Target Repository

`Stable-Diffusion-WebUI-Forge-Nunchaku`

---

## Error Details

When using video/DiT generative models such as Wan or Flux with Hires Fix (High-Resolution Fix) enabled, the following two types of errors occurred sequentially.

### Error 1 (During Latent-Space Upscaling)

```
ValueError: Input and output must have the same number of spatial dimensions,
but got input with spatial dimensions of [1, 184, 144] and output size of (368, 288).
Please provide input tensor in (N, C, d1, d2, ...,dK) format and output size in (o1, o2, ...,oK) format.
```

**Location:** `modules/processing.py` — inside `torch.nn.functional.interpolate` within `sample_hr_pass()`

### Error 2 (During Pixel-Space Upscaling)

```
TypeError: Cannot handle this data type: (1, 1, 1, 1024), |u1
```

**Location:** `modules/processing.py` — inside `Image.fromarray(x_sample)` within `sample_hr_pass()`

---

## Root Causes

### Background: Difference Between Standard SD Models and Wan/Flux Models

Standard SD/SDXL models represent their latent tensors in **4 dimensions (N, C, H, W)**:

| Dimension | Meaning |
|---|---|
| N | Batch Size |
| C | Number of Channels (typically 4 to 16 for latents) |
| H | Height (Latent Space) |
| W | Width (Latent Space) |

In contrast, **Wan/Flux-style video/DiT models** are designed to handle video frames, meaning their latent tensors are represented in **5 dimensions (N, C, T, H, W)**:

| Dimension | Meaning |
|---|---|
| N | Batch Size |
| C | Number of Channels |
| T | Temporal Dimension / Frames (1 for still images) |
| H | Height (Latent Space) |
| W | Width (Latent Space) |

Additionally, the **VAE-decoded image tensor** is returned in a different 5-dimensional layout: **(N, T, C, H, W)**:

| Dimension | Meaning |
|---|---|
| N | Batch Size |
| T | Temporal Dimension / Frames (1 for still images) |
| C | RGB Channels (3) |
| H | Height (Pixel Space) |
| W | Width (Pixel Space) |

### Cause of Error 1

`torch.nn.functional.interpolate` only accepts 2D spatial interpolation, which requires a **4D (N, C, H, W) tensor**.  
When a 5D tensor `(1, 16, 1, 184, 128)` was passed, PyTorch interpreted `[1, 184, 128]` as 3 spatial dimensions (T, H, W). This caused a mismatch with the target output size of `(368, 288)` (2 dimensions), raising the `ValueError`.

```
Input Tensor: (1, 16, 1, 184, 128)
               ↑  ↑  ↑
               N  C  T → PyTorch interprets this as a 3D spatial dimension [T, H, W] = [1, 184, 128]

Target Size: (368, 288) ← 2D

Spatial dimensions mismatch (3D vs 2D) → ValueError
```

### Cause of Error 2

`Image.fromarray` only accepts **3D (H, W, C) numpy arrays**.  
When `decoded_samples` was a 5D tensor `(1, 1, 3, 1472, 1024)` and was iterated over the batch dimension using `enumerate`, each sample became a 4D array `(1, 3, 1472, 1024)`.  
Performing `np.moveaxis(x_sample.cpu().numpy(), 0, 2)` on this 4D array resulted in `(3, 1472, 1, 1024)`, which PIL cannot process, leading to the `TypeError`.

```
decoded_samples: (1, 1, 3, 1472, 1024)
                  ↑  ↑
                  N  T ← The extra temporal dimension (T=1)

1 sample after enumerate: (1, 3, 1472, 1024) ← Still 4D
np.moveaxis(..., 0, 2) → (3, 1472, 1, 1024) ← Invalid for PIL

Expected shape for PIL fromarray: (H, W, C) = (1472, 1024, 3)
```

### 3. Detailed Explanations

#### Latent Path (Changeset A)

```python
if _5d := (len(samples.shape) == 5):
    samples = samples.squeeze(2)
```

Only when the `samples` tensor dimension is 5, we squeeze out dim 2 (temporal dimension T=1) to temporarily convert it to 4D.  
Using the walrus operator `:=`, we assign the check result directly to `_5d` for later reuse.

```python
samples = torch.nn.functional.interpolate(...)
```

Performs the latent-space upscaling on the now 4D `samples`.  
For standard SD/SDXL models (which are 4D by default), `_5d` is `False`, so no squeezing occurs.

```python
if _5d:
    samples = samples.unsqueeze(2)
```

Restores the temporal dimension at the original position using `unsqueeze(2)` after upscaling, only for 5D models.  
This ensures that the downstream sampler receives the 5D format matching the model's initialization.

#### Pixel Path (Changeset B)

```python
if len(decoded_samples.shape) == 5:
    decoded_samples = decoded_samples.squeeze(1)
```

If `decoded_samples` is a 5D tensor `(N, 1, C, H, W)`, we squeeze dim 1 (T=1) to format it to a standard 4D tensor `(N, C, H, W)`.  
This allows downstream logic (`enumerate` → `np.moveaxis` → `Image.fromarray`) to work correctly with 3D `(H, W, C)` arrays.

Note that after this block, `images_tensor_to_samples` is called to re-encode the image back to latents, which yields a standard 4D latent representation. Since pixel upscaling reconstructs the latent space through VAE, the resulting 4D shape is correct, and no unsqueezing is needed before the second sampler pass.

#### Conditional Branch Safety

| Model Type | `samples.shape` | `_5d` | Latent Path Squeeze | Pixel Path Squeeze |
|---|---|---|---|---|
| SD / SDXL / Anime models etc. | `(N, C, H, W)` -> 4D | `False` | **Skipped** | **Skipped** |
| Wan / Flux etc. | `(N, C, 1, H, W)` -> 5D | `True` | Executed | Executed |

Since the logic runs checks on `len(samples.shape) == 5` and `len(decoded_samples.shape) == 5`, the execution paths are completely decoupled. Standard 4D models bypass these operations entirely and remain unaffected.
