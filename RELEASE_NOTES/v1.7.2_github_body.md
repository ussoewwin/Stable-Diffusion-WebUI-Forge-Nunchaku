## 1. Summary

When Anima support was added (`a8f6373`), Lumina2 / Z-Image **entry detection** required `noise_refiner.k_norm`.  
**Nunchaku Z-Image Turbo** checkpoints use **`norm_k`** instead, so they no longer matched Lumina detection and fell through to **Nunchaku SDXL** fuzzy detection.

**Fix:** add `norm_k` as an alternative to `k_norm` in the Lumina entry `if` in `detection.py` — **one place only**.  
The rest of the v1.7.1 Lumina block, Anima block, and fuzzy SDXL block are unchanged.

---

## 2. Symptoms

Loading Nunchaku Z-Image Turbo as a standalone UNet checkpoint:

```
[Detection] Detected Nunchaku SDXL (fuzzy qweight match)
[Detection] Detected Nunchaku SDXL (fuzzy qweight match)
StateDict Keys: {'unet': 1235, 'vae': 244, 'text_encoder': 0, 'text_encoder_2': 0, 'ignore': 0}
AssertionError: You do not have CLIP state dict!
```

| Log line | Meaning |
|----------|---------|
| `Nunchaku SDXL (fuzzy qweight match)` | Lumina / Z-Image not detected; any `.qweight` key triggers SDXL Nunchaku |
| `text_encoder: 0` | No SDXL CLIP keys (Z-Image uses separate Qwen3 TE) |
| `You do not have CLIP state dict!` | Loader expects SDXL CLIP state dict |

**Example setup:**

| Component | Example |
|-----------|---------|
| UNet | `svdq-fp4_r128-z-image-turbo.safetensors` |
| Text encoder | Qwen3 4B safetensors (additional module) |
| VAE | zImageBase VAE |

## 3. Root cause (git history)

| Phase | Commit | Lumina entry condition | Nunchaku ZIT |
|-------|--------|------------------------|--------------|
| Before Anima | `a8f6373^` | `cap_embedder.1.weight` only | Works |
| Anima added | `a8f6373` | `cap_embedder` + **`noise_refiner.k_norm`** | Broken |
| v1.7.1 tag | `v1.7.1` (`13ca02afd`) | same (`k_norm` only) | Broken |
| After this fix | working tree | `k_norm` **OR `norm_k`** | Expected to work |

**Why `k_norm` was added (Anima):** exclude cap-only Anima-family ckpts (e.g. wai) from Lumina2. That guard is correct; **`norm_k` was not considered** for Nunchaku exports.

## 4. Why `k_norm` vs `norm_k` matters

### 4.1 Standard NextDiT / Comfy

ComfyUI `comfy/model_detection.py` also requires `k_norm`:

```python
if '{}cap_embedder.1.weight'.format(key_prefix) in state_dict_keys \
   and '{}noise_refiner.0.attention.k_norm.weight'.format(key_prefix) in state_dict_keys:
```

Non-Nunchaku checkpoints use `k_norm` key names.

### 4.2 Nunchaku Z-Image Turbo export

Nunchaku quantized exports use **`norm_k` / `norm_q`**, not `k_norm` / `q_norm`.

`backend/nn/svdq.py` remaps at **load time** inside `patch_z_image_state_dict()`:

```python
elif "attention.norm_k" in key:
    patched_state_dict[key.replace("norm_k", "k_norm")] = value
```

**Important:** remap runs in **`NextDiT.load_state_dict`**, after detection.  
**`detect_unet_config()` sees raw keys** — no `k_norm`, only `norm_k` → v1.7.1 entry fails.

### 4.3 `cap_feat_dim` (related, separate issue)

Z-Image Turbo HF config:

```json
"cap_feat_dim": 2560,
"dim": 3840
```

v1.7.1 Lumina block always sets these from `cap_embedder.1.weight` (unchanged by this fix):

```python
w = state_dict["{}cap_embedder.1.weight".format(key_prefix)]
dit_config["dim"] = int(w.shape[0])           # 3840
dit_config["cap_feat_dim"] = int(w.shape[1])  # 2560
```

A **`cap_feat_dim` shape mismatch** (5120 vs 2560) came from a **different regression** (Comfy import attempt that dropped post-merge fields). That is **not** fixed by this `norm_k` change alone.

## 6. Fix (single diff vs v1.7.1 tag)

**File:** `modules_forge/packages/huggingface_guess/detection.py`  
**Location:** Lumina2 entry `if`, immediately after Anima early return.

### 6.1 v1.7.1 (broken for Nunchaku ZIT)

```python
if (
    "{}cap_embedder.1.weight".format(key_prefix) in state_dict_keys
    and "{}noise_refiner.0.attention.k_norm.weight".format(key_prefix) in state_dict_keys
):
```

### 6.2 After fix

```python
if (
    "{}cap_embedder.1.weight".format(key_prefix) in state_dict_keys
    and (
        "{}noise_refiner.0.attention.k_norm.weight".format(key_prefix) in state_dict_keys
        or "{}noise_refiner.0.attention.norm_k.weight".format(key_prefix) in state_dict_keys
    )
):
```

### 6.3 Verify diff

```bash
git diff v1.7.1 -- modules_forge/packages/huggingface_guess/detection.py
```

Only the three lines adding `or ... norm_k ...` should appear.

### 6.4 Lumina block body (lines ~63–125)

**Unchanged** from v1.7.1, including:

- `cap_feat_dim`, `dim`, `n_layers`, `qk_norm`
- `dim == 2304` (Lumina2), `3840` (Z-Image + `nunchaku`), `1920` (Z-Image Base)
- Distilled FFN (`ffn_input_dim == 1920`)
- `ffn_dim_multiplier` inference from `feed_forward.w1`

## 9. Anima false-positive guard still works

| Checkpoint | Keys | Result |
|------------|------|--------|
| Anima (main) | `x_embedder.proj.1.weight` + `llm_adapter.*` | Anima early return |
| Anima wai (cap only) | `cap_embedder` only, no `noise_refiner` | Lumina **No** |
| Standard Lumina2 / Z-Image | `cap_embedder` + `k_norm` | Lumina **Yes** |
| Nunchaku Z-Image Turbo | `cap_embedder` + `norm_k` | Lumina **Yes** (this fix) |

We did **not** revert to pre-Anima `cap_embedder`-only entry (that would re-break wai discrimination).
