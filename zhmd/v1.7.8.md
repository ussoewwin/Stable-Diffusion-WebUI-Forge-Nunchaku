# Hires Fix 5D 张量兼容性补丁说明

## 目标仓库

`Stable-Diffusion-WebUI-Forge-Nunchaku`

---

## 错误详情

在启用 Hires Fix（高分辨率修复）的情况下使用 Wan 或 Flux 等视频/DiT 生成模型时，会依次发生以下两种类型的错误。

### 错误 1（在 Latent 空间超分过程中）

```
ValueError: Input and output must have the same number of spatial dimensions,
but got input with spatial dimensions of [1, 184, 144] and output size of (368, 288).
Please provide input tensor in (N, C, d1, d2, ...,dK) format and output size in (o1, o2, ...,oK) format.
```

**位置：** `modules/processing.py` — `sample_hr_pass()` 方法中调用 `torch.nn.functional.interpolate` 内部

### 错误 2（在像素空间超分过程中）

```
TypeError: Cannot handle this data type: (1, 1, 1, 1024), |u1
```

**位置：** `modules/processing.py` — `sample_hr_pass()` 方法中调用 `Image.fromarray(x_sample)` 内部

---

## 根本原因

### 背景：标准 SD 模型与 Wan/Flux 模型的区别

标准的 SD/SDXL 模型将其 latent 张量表示为 **4 维 (N, C, H, W)**：

| 维度 | 含义 |
|---|---|
| N | Batch 大小 |
| C | 通道数（对于 latent，通常为 4 到 16） |
| H | 高度（Latent 空间） |
| W | 宽度（Latent 空间） |

相比之下，**Wan/Flux 风格的视频/DiT 模型**旨在处理视频帧，这意味着它们的 latent 张量表示为 **5 维 (N, C, T, H, W)**：

| 维度 | 含义 |
|---|---|
| N | Batch 大小 |
| C | 通道数 |
| T | 时间维度 / 帧数（对于静态图像为 1） |
| H | 高度（Latent 空间） |
| W | 宽度（Latent 空间） |

此外，**VAE 解码后的图像张量**以不同的 5 维布局返回：**(N, T, C, H, W)**：

| 维度 | 含义 |
|---|---|
| N | Batch 大小 |
| T | 时间维度 / 帧数（对于静态图像为 1） |
| C | RGB 通道（3） |
| H | 高度（像素空间） |
| W | 宽度（像素空间） |

### 错误 1 的原因

`torch.nn.functional.interpolate` 仅接受 2D 空间插值，这需要 **4D (N, C, H, W) 张量**。  
当传入 5D 张量 `(1, 16, 1, 184, 128)` 时，PyTorch 将 `[1, 184, 128]` 解释为 3 个空间维度（T, H, W）。这导致与目标输出尺寸 `(368, 288)`（2 个维度）不匹配，从而抛出 `ValueError`。

```
输入张量: (1, 16, 1, 184, 128)
           ↑  ↑  ↑
           N  C  T → PyTorch 将此解释为 3D 空间维度 [T, H, W] = [1, 184, 128]

目标尺寸: (368, 288) ← 2D

空间维度不匹配 (3D vs 2D) → ValueError
```

### 错误 2 的原因

`Image.fromarray` 仅接受 **3D (H, W, C) numpy 数组**。  
当 `decoded_samples` 为 5D 张量 `(1, 1, 3, 1472, 1024)`，且使用 `enumerate` 在 batch 维度上进行迭代时，每个样本都变成了 4D 数组 `(1, 3, 1472, 1024)`。  
在此 4D 数组上执行 `np.moveaxis(x_sample.cpu().numpy(), 0, 2)` 会导致 `(3, 1472, 1, 1024)` 的形状，PIL 无法处理，从而导致 `TypeError`。

```
decoded_samples: (1, 1, 3, 1472, 1024)
                  ↑  ↑
                  N  T ← 额外的时间维度 (T=1)

enumerate 后的 1 个样本: (1, 3, 1472, 1024) ← 仍为 4D
np.moveaxis(..., 0, 2) → (3, 1472, 1, 1024) ← 对 PIL 无效

PIL fromarray 期望的形状: (H, W, C) = (1472, 1024, 3)
```

**修改后（修改）：**

```python
if self.latent_scale_mode is not None:
    for i in range(samples.shape[0]):
        save_intermediate(samples, i)

    # Some models (e.g. Flux/Wan) produce 5D latents (N, C, 1, H, W).
    # interpolate needs 4D, so squeeze/unsqueeze around it.
    if _5d := (len(samples.shape) == 5):
        samples = samples.squeeze(2)

    samples = torch.nn.functional.interpolate(
        samples,
        size=(target_height // opt_f, target_width // opt_f),
        mode=self.latent_scale_mode["mode"],
        antialias=self.latent_scale_mode["antialias"]
    )

    if _5d:
        samples = samples.unsqueeze(2)

    if getattr(self, "inpainting_mask_weight", shared.opts.inpainting_mask_weight) < 1.0:
        image_conditioning = self.img2img_image_conditioning(decode_first_stage(self.sd_model, samples), samples)
    else:
        image_conditioning = self.txt2img_image_conditioning(samples)
else:
    # Some models (e.g. Flux/Wan) produce 5D decoded output (N, 1, C, H, W).
    # Squeeze the extra temporal dim for PIL/numpy processing.
    if len(decoded_samples.shape) == 5:
        decoded_samples = decoded_samples.squeeze(1)

    lowres_samples = torch.clamp((decoded_samples + 1.0) / 2.0, min=0.0, max=1.0)

    batch_images = []
    for i, x_sample in enumerate(lowres_samples):
        x_sample = 255.0 * np.moveaxis(x_sample.cpu().numpy(), 0, 2)
        x_sample = x_sample.astype(np.uint8)
        image = Image.fromarray(x_sample)
        ...
```

### 3. 详细说明

#### Latent 路径（变更集 A）

```python
if _5d := (len(samples.shape) == 5):
    samples = samples.squeeze(2)
```

仅当 `samples` 张量维度为 5 时，我们 squeeze 出 dim 2（时间维度 T=1）以临时转换为 4D。  
使用 walrus 运算符 `:=`，我们将检查结果直接分配给 `_5d` 以备后用。

```python
samples = torch.nn.functional.interpolate(...)
```

在现在的 4D `samples` 上执行 latent 空间超分。  
对于标准的 SD/SDXL 模型（默认情况下是 4D），`_5d` 为 `False`，因此不会发生 squeeze。

```python
if _5d:
    samples = samples.unsqueeze(2)
```

在超分之后，仅针对 5D 模型使用 `unsqueeze(2)` 在原始位置恢复时间维度。  
这确保了下游 sampler 能够接收到与模型初始化相匹配的 5D 格式。

#### 像素路径（变更集 B）

```python
if len(decoded_samples.shape) == 5:
    decoded_samples = decoded_samples.squeeze(1)
```

如果 `decoded_samples` 是 5D 张量 `(N, 1, C, H, W)`，我们 squeeze dim 1 (T=1) 以将其格式化为标准的 4D 张量 `(N, C, H, W)`。  
这使得下游逻辑（`enumerate` → `np.moveaxis` → `Image.fromarray`）能够正确处理 3D `(H, W, C)` 数组。

请注意，在此块之后，将调用 `images_tensor_to_samples` 将图像重新编码回 latent，从而产生标准的 4D latent 表示。由于像素超分通过 VAE 重建了 latent 空间，因此得到的 4D 形状是正确的，并且在第二遍 sampler 之前不需要 unsqueeze。

#### 条件分支安全性

| 模型类型 | `samples.shape` | `_5d` | Latent 路径 Squeeze | 像素路径 Squeeze |
|---|---|---|---|---|
| SD / SDXL / 动漫模型 等 | `(N, C, H, W)` -> 4D | `False` | **跳过** | **跳过** |
| Wan / Flux 等 | `(N, C, 1, H, W)` -> 5D | `True` | 执行 | 执行 |

由于逻辑对 `len(samples.shape) == 5` 和 `len(decoded_samples.shape) == 5` 运行检查，执行路径是完全解耦的。标准 4D 模型完全绕过这些操作，不受影响。
