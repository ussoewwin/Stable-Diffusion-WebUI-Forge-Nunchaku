## 1. 现象与原因

| 项目 | 内容 |
|------|------|
| **现象** | 使用 Pony 系 SDXL LoRA（例如 `cureflora.pony.safetensors`）时：**只有 UNet 似乎生效 / CLIP 侧无效果**，或控制台出现 `[LORA] LoRA mismatch`，**整个 LoRA 被拒绝** |
| **直接原因** | 将 LoRA 文件中的 CLIP 键（`lora_te1_*`）映射到模型权重键的 **`model_lora_keys_clip()`** 与 **实际 CLIP `state_dict` 键布局** 不一致 |
| **结构原因** | Forge SDXL 通过 **IntegratedCLIP** 加载 CLIP，键为 **`clip_l.transformer.encoder.layers.*`**。旧代码只查找 **`clip_l.transformer.text_model.encoder.layers.*`** |

---

## 2. 为何 Forge 的 CLIP 键会“变样”

### 2.1 IntegratedCLIP 结构

SDXL 在 `backend/loader.py` 中将 `CLIPTextModel` 包装为 **`IntegratedCLIP`**（`backend/nn/clip.py`）。仅使用 `self.transformer = cls(config)`，没有 HuggingFace 风格的 `text_model` 包装层。

### 2.2 加载器中的键规范化

加载 checkpoint 时（`load_huggingface_component` 附近），形如

```
text_model.encoder.layers.0....
```

的键会去掉前缀，只加上 **`transformer.{clean}`**。因此运行时的键形如：

```
clip_l.transformer.encoder.layers.0.self_attn.k_proj.weight
```

**不会**变成 `clip_l.transformer.text_model.encoder.layers.*`。

### 2.3 修复前 `model_lora_keys_clip` 的假设

修复前，在 `state_dict` 中只查找：

```
clip_l.transformer.text_model.encoder.layers.{block}.{layer}.weight
```

在 IntegratedCLIP 与上述规范化下，**这些键不存在** → `key_map` 中几乎没有 CLIP encoder 条目 → Pony LoRA 的 `lora_te1_*` 无法匹配。

## 3. LoRA 应用流程（修复所在位置）

```
[LoRA .safetensors]
        ↓
extensions-builtin/sd_forge_lora/networks.py
  load_lora_for_models()
        ↓
model_lora_keys_unet()  → UNet key_map
model_lora_keys_clip()  → CLIP key_map   ← ★ 修复位置
        ↓
load_lora(lora_dict, key_map)  (modules_forge/packages/comfy/lora.py)
  将 LoRA 键与模型权重键绑定；构建 patches
        ↓
未匹配键 > LoRA 键总数的 **50%** → 拒绝整个文件（[LORA] LoRA mismatch）
        ↓
model.add_patches() / clip.add_patches()
```

### 3.1 `key_map` 的含义

`model_lora_keys_clip()` 构建如下字典：

| key（LoRA 文件侧逻辑名） | value（模型 `state_dict` 中的实际键） |
|--------------------------|----------------------------------------|
| `lora_te1_text_model_encoder_layers_0_self_attn_k_proj` | `clip_l.transformer.encoder.layers.0.self_attn.k_proj.weight` |
| `text_encoder.text_model.encoder.layers.0.self_attn.k_proj`（diffusers 风格） | 同上 |

`load_lora()` 用 **key**（左）作为 LoRA 文件中 `*.lora_up` / `*.lora_down` 的前缀，对 **value**（右）应用 patch。

### 3.2 50% 门槛（`networks.py` 约 79–86 行）

```python
_unmatches = len(lora_unmatch)

if _unmatches / len(lora) > 0.5:
    print(f"[LORA] LoRA mismatch for {model_flag}: {filename}")
    return model, clip

if _unmatches > 0:
    print(f"[LORA] Loading {filename} for {model_flag} with {_unmatches} unmatched keys")
```

若 CLIP 键几乎全部匹配失败，即使 UNet 键能匹配，**整个文件也会被跳过**。表现上可能是“LoRA 完全无效”，而非“只有 UNet 生效”。

## 4. 修复内容（当前 `main` 实现）

**文件：** `modules_forge/packages/comfy/lora.py`  
**函数：** `model_lora_keys_clip()`（约 107–174 行）  
**来源：** `3a8ea0c` / `3d1950d` / `08e6e70`

### 4.1 `LORA_CLIP_MAP`（未改）

将 LoRA 文件内层名（下划线分隔）映射到模型内属性名：

| 模型侧（`encoder.layers` 内） | LoRA 后缀 |
|-----------------------------|-----------|
| `self_attn.k_proj` | `self_attn_k_proj` |
| `self_attn.q_proj` | `self_attn_q_proj` |
| `self_attn.v_proj` | `self_attn_v_proj` |
| `self_attn.out_proj` | `self_attn_out_proj` |
| `mlp.fc1` | `mlp_fc1` |
| `mlp.fc2` | `mlp_fc2` |

### 4.2 核心修复：`clip_layer_paths` 循环

对 `clip_h`、`clip_l`、`clip_g` 各分支，按顺序尝试 **两种相对路径**（实现上会加上 `clip_l.` 等前缀并在 `sdk` 中查找）：

```python
# transformers 4.x–5.5: clip_*.transformer.text_model.encoder.layers.*
# transformers 5.6+（IntegratedCLIP + f1c299e 加载器）: clip_*.transformer.encoder.layers.*
clip_layer_paths = (
    "transformer.text_model.encoder.layers.{}.{}.weight",
    "transformer.encoder.layers.{}.{}.weight",
)
```

对每个 `(block, layer)`：

1. 将上述路径加上 `clip_h.` / `clip_l.` / `clip_g.` 前缀，检查是否存在于 `sdk`（`model.state_dict().keys()`）。
2. 若存在，向 `key_map` 注册多种 LoRA 键形式：
   - `lora_te1_text_model_encoder_layers_{block}_{layer}`（SDXL / Pony 标准）
   - `text_encoder.text_model.encoder.layers.{block}.{layer}`（diffusers 格式）
   - `lora_te2_*`（存在 `clip_l` 与 `clip_g` 的 SDXL 双文本编码器时，用于 `clip_g`）

不在 `sdk` 中的路径会跳过。IntegratedCLIP 下通常第一条路径匹配不到，第二条命中。

### 4.3 注释中的意图（约 114–118 行）

- **TF 4.x–5.5：** `transformer.text_model.encoder.layers.*`
- **TF 5.6+ / IntegratedCLIP：** `transformer.encoder.layers.*`（无 `text_model`）

Pony / Forge Classic Neo 的 SDXL 管线属于后者。

## 5. 与另一实现（`45a0101`）的差异

本地提交 `45a0101` 使用辅助函数 `_resolve_clip_encoder_layer_weight_key()`，**查找顺序相反**：

| 实现 | 查找顺序 |
|------|----------|
| **`45a0101`** | ① `transformer.encoder.layers` → ② `transformer.text_model.encoder.layers` |
| **当前 `main`** | ① `text_model.encoder` → ② `encoder.layers` |

在 **仅 IntegratedCLIP** 时，真实键在 `encoder.layers` 下，**两种方式应得到相同键，Pony LoRA 均应生效**。

仅当 `state_dict` 中 **两种键布局并存** 时才有差异：

- 当前 `main` 版：优先 `text_model` 路径  
- `45a0101`：优先 `encoder` 路径  

**当前 `main` 的 `lora.py` 采用 `clip_layer_paths` 实现**（合并时选择 `origin/main`）。`45a0101` 的辅助函数 **不在当前文件中**（仅保留在历史提交中）。

## 7. Pony LoRA 文件键（参考）

典型 SDXL Pony LoRA 包含：

- **UNet：** `lora_unet_*` → 通常通过 `model_lora_keys_unet` 匹配  
- **CLIP-L：** `lora_te1_text_model_encoder_layers_{N}_{self_attn_k_proj, ...}` → **本次修复目标**  
- **CLIP-G（SDXL）：** `lora_te2_*` → 用于 `clip_g`（当同时存在 `clip_l` 与 `clip_g` 时）

修复后，`lora_te1_*` 绑定到 `clip_l.transformer.encoder.layers.*`，**提示词侧 LoRA 效果**得以生效。
