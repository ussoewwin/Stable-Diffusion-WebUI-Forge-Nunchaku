# Version 1.8.1 — 移除 Nunchaku SDXL 代码（第一阶段）

本次发布是一个**维护 / 清理**版本。它移除了不再使用的、无用的 Nunchaku SDXL 实现，同时保证对常规 SDXL、fp16 / fp8 / int8，以及其他模型的 Nunchaku（Flux1、Qwen Image、Z-Image / ZIT）**没有任何行为变化**。

本次发布**没有新功能**，也**没有面向用户的 UI 变化**。

---

## 1. 为什么要清理

Nunchaku SDXL 路径（`SVDQUNet2DConditionModel` 及其专用 CLIP 转换器）是一次早期实验，已不再属于受支持的模型集合。它遗留了：

- 仅被其自身调用方导入的专用模块。
- 散落在加载器、LoRA 网络层以及 RES4LYF beta 采样器中的 SDXL 专用分支。
- 孤立 / 重复的文件。

保留这些无用代码会增加意外回归的风险，并使 Nunchaku 代码路径（Flux1 / Qwen Image / Z-Image）更难阅读。第一阶段将其外科式地移除。

---

## 2. 删除的文件

| 文件 | 删除行数 | 作用 |
|---|---|---|
| **`backend/nn/nunchaku_sdxl_unet.py`** | 2447 | 定义了 `SVDQUNet2DConditionModel`（Nunchaku SDXL UNet）以及全部 SDXL 专用的 LoRA 映射 / 键转换 / QKV 融合逻辑。 |
| **`backend/nn/nunchaku_sdxl_clip.py`** | 359 | 专用的 Nunchaku SDXL CLIP → Forge 格式转换器（`convert_nunchaku_clip_to_forge_format`）。 |
| **`backend/nn/nunchaku_sdxl_unet_append.py`** | 48 | 孤立的重复 `SVDQUNet2DConditionModel` / `patch_nunchaku_sdxl`（没有实际调用方）。 |

这三个文件仅能通过第 3 节中移除的 SDXL 专用分支到达，因此删除它们不会影响任何其他模型。

---

## 3. 外科式编辑（移除 SDXL 专用分支）

### 3.1 `backend/loader.py`

**UNet 分发** —— 移除了针对 `UNet2DConditionModel` 的 `nunchaku` 特例，使 SDXL UNet 始终走标准的集成路径：

```python
if cls_name == "UNet2DConditionModel":
    model_loader = lambda c: IntegratedUNet2DConditionModel.from_config(c)
```

（此前当设置了 `guess.nunchaku` 时，该分支会进入 `SVDQUNet2DConditionModel(c)`。）

**CLIP 转换** —— 从 `forge_loader` 中移除了整个 Nunchaku-SDXL CLIP 转换块（那段调用 `convert_nunchaku_clip_to_forge_format` 的 `should_convert` / `SDXL` 类型嗅探逻辑）。该块内部已明确禁止对 Flux 与 Qwen 的 CLIP 进行转换，因此它们的行为保持不变。

> 注意：INT8 加载器分支（`int8_tensorwise`）以及 Flux / Qwen / Z-Image 的 Transformer 分发**未被改动**。

### 3.2 `extensions-builtin/sd_forge_lora/networks.py`

移除了两个仅针对 SDXL 的 LoRA 块，它们都以 `isinstance(..., SVDQUNet2DConditionModel)` 为门控：

- `load_lora_for_models` 中的**添加**块（向 `diffusion_model.loras` 追加）。
- `load_networks` 中的**清除**块。

ZIT（`NextDiT`）、Nunchaku Qwen Image、Flux1，以及标准 FP 的 LoRA 路径都原样保留。

### 3.3 RES4LYF beta 采样器

这四个采样器各自带有一个 `is_nunchaku_sdxl` 标志，仅用于一个调试 / 标签字符串（`model_type_str = "Nunchaku SDXL"`）。该标志声明、`SVDQUNet2DConditionModel` 导入、`isinstance` 分支，以及每一个 `elif is_nunchaku_sdxl:` 标签分支都被移除：

- `modules/RES4LYF/beta/rk_sampler_beta.py`
- `modules/RES4LYF/beta/rk_method_beta.py`
- `modules/RES4LYF/beta/rk_guide_func_beta.py`
- `modules/RES4LYF/beta/rk_noise_sampler_beta.py`

`Nunchaku QwenImage`、`Nunchaku FLUX1`、`SDXL` 与 `FLUX1` 的检测标签保持不变，因此对每个受支持模型而言，采样器行为完全一致。

---

## 4. 影响分析（无回归）

- **常规 SDXL / fp16 / fp8 / int8** —— 现在 `UNet2DConditionModel` 唯一的路径就是标准的 `IntegratedUNet2DConditionModel`；INT8（`int8_tensorwise`）的提前返回分支未被改动。
- **Nunchaku Flux1 / Qwen Image / Z-Image** —— 它们的 Transformer 类位于 `backend/nn/svdq.py`（以及 `_qwen_lora.py` / `_zimage_lora.py`），这些文件均不引用被删除的 SDXL 文件。所有被删除的分支都带有明确排除这些模型的门控。
- **LoRA** —— SDXL、Flux1、Qwen Image 与 Z-Image 的 LoRA 路径保持不变；仅移除了无用的 SDXL-Nunchaku LoRA 添加 / 清除分支。
- **`modules/ComfyUI-nunchaku-unofficial-loader/`** —— 不在范围内，未被改动。

---

## 5. 验证

- 合计：**9 个文件变更，新增 28 行(+)，删除 2960 行(-)**。
