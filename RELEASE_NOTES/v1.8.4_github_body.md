# Version 1.8.4 — Krea2 quantized TE load fix (Issue #3)

This release fixes **quantized Krea2 text-encoder load** when `get_layout_class(...)` returns `None` ([Issue #3](https://github.com/ussoewwin/Stable-Diffusion-WebUI-Forge-Nunchaku/issues/3)). Vendored `ComfyUI-master/` sources are not edited.

It also relaxes the root pin to **`safetensors>=0.8.0`** so `diffusers>=0.39.0` can resolve without conflicting with the old `safetensors==0.8.0rc0` pin.

---

## 1. Summary

| Item | Detail |
|---|---|
| Primary fix | Forge runtime dequant when MixedPrecision `layout_cls` is `None` |
| Symptom | `AttributeError: 'NoneType' object has no attribute 'Params'` on quantized Krea2 TE load |
| Issue | [#3](https://github.com/ussoewwin/Stable-Diffusion-WebUI-Forge-Nunchaku/issues/3) |
| Dependency | `safetensors>=0.8.0` (with existing `diffusers>=0.39.0`) |
| Unchanged | Anima RMS+RoPE fuse (v1.8.3); Krea2 **depth ControlNet** still not supported; Attention UI |

---

## 2. Symptom (reporter traceback)

Loading a **quantized** Krea2 checkpoint (MixedPrecision / `*.comfy_quant` on the Qwen3-VL TE path) can fail with:

```text
File ".../ComfyUI-master/comfy/ops.py", line 1125, in _load_quantized_module
    params = layout_cls.Params(**scales, orig_dtype=compute_dtype, orig_shape=module._orig_shape)
AttributeError: 'NoneType' object has no attribute 'Params'
```

Call chain (abbreviated): `forge_loader` → `Qwen3VLModel` / `CLIPType.KREA2` → TE `load_state_dict` → MixedPrecision `Linear._load_from_state_dict` → `_load_quantized_module`.

---

## 3. Cause

`_load_quantized_module` does `layout_cls = get_layout_class(...)`. When that returns **`None`**, the next line calls `layout_cls.Params` and crashes. The pasted Issue #3 log shows this failure; it does **not** include kitchen import lines by itself.

---

## 4. Forge fix (no `ComfyUI-master/` edits)

| Piece | Role |
|---|---|
| `backend/patch_comfy_quant_layout_fallback.py` | Runtime wrap of `comfy.ops._load_quantized_module` (and Embedding load when needed) |
| `backend/loader.py` | Calls `ensure_comfy_quant_layout_fallback_patch()` from `forge_loader`, `_comfy_load_te`, and `_load_krea2_mixed_precision_unet` |

When `get_layout_class(layout)` is `None` for supported formats (`float8_e4m3fn` / `float8_e5m2` / `int8_tensorwise`), Forge **dequantizes to a float `Parameter`** instead of building a `QuantizedTensor`. TE paths already use `full_precision_mm=True` semantics for inference, so float weights are valid.

Console markers:

```text
[Forge] comfy_quant layout fallback patch active (dequant when kitchen layout is None)
[Forge] comfy_kitchen layout missing for <format> — dequantizing <layer> to <dtype> (Issue #3 fallback)
```

Formats that still require a real kitchen layout (`mxfp8` / `nvfp4` / `convrot_w4a4`) raise a clear `RuntimeError` instead of `None.Params`.

---

## 5. Dependency: `safetensors>=0.8.0`

Root `requirements.txt`:

```text
diffusers>=0.39.0
safetensors>=0.8.0
```

`diffusers 0.39.0` requires `safetensors>=0.8.0`. The previous pin `safetensors==0.8.0rc0` caused `ResolutionImpossible` on launch (`pip install -r requirements.txt`). The pin is now a lower bound so a stable `0.8.0+` wheel can install.

---

## 6. Out of scope

- Krea2 **depth ControlNet** remains unsupported (same as the Issue #3 owner reply on v1.8.2 basic support).
- `ComfyUI-master/` is not modified.
- Anima fuse / FA-2 logging from **v1.8.3** are unchanged by this release’s primary fix (they remain in tree from v1.8.3).
