# Version 1.8.5 — ComfyUI-master 同步与 comfy-kitchen 升级

本版本将远程用户所需的 **内嵌 `ComfyUI-master` 树** 与 **kitchen 版本** 推送到与当前 Forge 导入环境一致的状态（含 INT8 ConvRot / `TensorCoreConvRotW4A4Layout`）。Forge 运行时依赖仍由**仓库根目录** `requirements.txt` 安装。

---

## 1. 概述

| 项目 | 详情 |
|---|---|
| 主要变更 | 将内嵌 **`ComfyUI-master`** 同步到 Forge 导入所用的最新上游树 |
| Kitchen（内嵌树） | `ComfyUI-master/requirements.txt` 中 **`comfy-kitchen==0.2.22`** |
| Kitchen（Forge 运行时） | 根目录 **`requirements.txt`** 仍为 **`comfy-kitchen>=0.2.21`**（不变；Forge 的 `pip install -r` 读它） |
| 原因 | 旧远程树 / 旧 kitchen 可能出现 `cannot import name 'TensorCoreConvRotW4A4Layout'`，并导致 FP8/INT8 kitchen 路径整体失效 |
| 不变 | Issue #3 TE 反量化回退（v1.8.4）；Anima RMS+RoPE 融合（v1.8.3）；Krea2 depth ControlNet 仍不支持 |

---

## 2. 背景

Forge 嵌入 **`ComfyUI-master/`** 副本，用于模型 / 量化 / ops 导入。本地开发已使用较新的 master + kitchen，而 **`origin/main`** 曾滞后。仅拉取已发布树的用户因此可能缺少：

- 较新的 `ComfyUI-master` 模块（JoyImage、Anima LLLite、API 节点、检测更新、测试等）
- 能导出 **`TensorCoreConvRotW4A4Layout`** 的 kitchen 版本

`comfy/quant_ops.py` 将该符号与 INT8/FP8 layout **一并导入**。若已安装的 kitchen 过旧，**整个** kitchen 导入失败，量化路径随之降级。

---

## 3. 变更内容

### 3.1 内嵌 `ComfyUI-master`

同步 Forge 导入所用内嵌树，主要包括（非完整列表）：

- JoyImage 模型 / TE / 节点
- Anima LLLite
- HeyGen / Sync.so API 节点
- 模型检测、supported models、attention / cosmos predict2 更新
- 单元 / execution 测试更新
- `ComfyUI-master/requirements.txt` → **`comfy-kitchen==0.2.22`**

### 3.2 Forge 根目录依赖

根目录 `requirements.txt` 已包含 **`comfy-kitchen>=0.2.21`**。该 pin 才是 Forge 安装/更新时实际使用的约束。拉取 v1.8.5 后请执行：

```text
pip install -r requirements.txt
```

确保当前 venv 中的 kitchen 真正具备现行 layout。

---

## 4. 安装 / 更新说明

1. `git pull`（或下载）本版本。
2. 在 Forge **根目录**执行 **`pip install -r requirements.txt`**（不要用 `ComfyUI-master/requirements.txt`）。
3. 重启 Forge。
4. 原生 INT8 ConvRot 检查点请优先使用 **Comfy-Org / ComfyUI 原生** 权重。**ComfyUI-INT8-Fast** 导出格式不同，需转换后才能走原生路径。

---

## 5. 范围外

- 不更新 kitchen 时，对缺失 `TensorCoreConvRotW4A4Layout` 的 soft-import 恢复（可选加固；不在本版本）。
- checkpoint→LoRA 静默回退的加固。
- Krea2 **depth ControlNet**。
- 在 Forge 内实现或支持仅适用于 ComfyUI-INT8-Fast 的权重格式。
