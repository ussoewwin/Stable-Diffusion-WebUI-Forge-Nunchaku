# Version 1.8.4 — Krea2 量化 TE 加载修复（Issue #3）

本版本修复当 `get_layout_class(...)` 返回 `None` 时 **量化 Krea2 文本编码器加载** 崩溃的问题（[Issue #3](https://github.com/ussoewwin/Stable-Diffusion-WebUI-Forge-Nunchaku/issues/3)）。供应商目录 `ComfyUI-master/` **不会**被修改。

同时将根目录依赖放宽为 **`safetensors>=0.8.0`**，避免旧 pin `safetensors==0.8.0rc0` 与 `diffusers>=0.39.0` 冲突导致启动时 pip 解析失败。

---

## 1. 概述

| 项目 | 详情 |
|---|---|
| 主要修复 | MixedPrecision 的 `layout_cls` 为 `None` 时，Forge 运行时反量化 |
| 现象 | 量化 Krea2 TE 加载时出现 `AttributeError: 'NoneType' object has no attribute 'Params'` |
| Issue | [#3](https://github.com/ussoewwin/Stable-Diffusion-WebUI-Forge-Nunchaku/issues/3) |
| 依赖 | `safetensors>=0.8.0`（配合已有的 `diffusers>=0.39.0`） |
| 不变 | Anima RMS+RoPE 融合（v1.8.3）；Krea2 **depth ControlNet** 仍不支持；Attention UI |

---

## 2. 现象（报告者 traceback）

加载 **量化** Krea2 检查点（Qwen3-VL TE 路径上的 MixedPrecision / `*.comfy_quant`）时可能失败：

```text
File ".../ComfyUI-master/comfy/ops.py", line 1125, in _load_quantized_module
    params = layout_cls.Params(**scales, orig_dtype=compute_dtype, orig_shape=module._orig_shape)
AttributeError: 'NoneType' object has no attribute 'Params'
```

调用链（摘要）：`forge_loader` → `Qwen3VLModel` / `CLIPType.KREA2` → TE `load_state_dict` → MixedPrecision `Linear._load_from_state_dict` → `_load_quantized_module`。

---

## 3. 原因

`_load_quantized_module` 执行 `layout_cls = get_layout_class(...)`。当返回 **`None`** 时，下一行调用 `layout_cls.Params` 即崩溃。Issue #3 粘贴日志显示的是该失败；**本身并不包含** kitchen import 相关行。

---

## 4. Forge 修复（不修改 `ComfyUI-master/`）

| 部件 | 作用 |
|---|---|
| `backend/patch_comfy_quant_layout_fallback.py` | 运行时包装 `comfy.ops._load_quantized_module`（必要时含 Embedding 加载） |
| `backend/loader.py` | 在 `forge_loader`、`_comfy_load_te`、`_load_krea2_mixed_precision_unet` 中调用 `ensure_comfy_quant_layout_fallback_patch()` |

当支持的格式（`float8_e4m3fn` / `float8_e5m2` / `int8_tensorwise`）上 `get_layout_class(layout)` 为 `None` 时，Forge **反量化为 float `Parameter`**，而不构建 `QuantizedTensor`。TE 路径推理已使用 `full_precision_mm=True` 语义，故 float 权重有效。

控制台标记：

```text
[Forge] comfy_quant layout fallback patch active (dequant when kitchen layout is None)
[Forge] comfy_kitchen layout missing for <format> — dequantizing <layer> to <dtype> (Issue #3 fallback)
```

仍需真实 kitchen layout 的格式（`mxfp8` / `nvfp4` / `convrot_w4a4`）会抛出明确的 `RuntimeError`，而不是 `None.Params`。

---

## 5. 依赖：`safetensors>=0.8.0`

仓库根目录 `requirements.txt`：

```text
diffusers>=0.39.0
safetensors>=0.8.0
```

`diffusers 0.39.0` 要求 `safetensors>=0.8.0`。旧 pin `safetensors==0.8.0rc0` 会在启动时 `pip install -r requirements.txt` 触发 `ResolutionImpossible`。现改为下限，以便安装稳定版 `0.8.0+` wheel。

---

## 6. 范围外

- Krea2 **depth ControlNet** 仍不支持（与 Issue #3 回复中关于 v1.8.2 基础支持的说明一致）。

- **v1.8.3** 的 Anima 融合 / FA-2 日志不由本版本的主要修复改写（仍保留在树中）。
