# Version 1.8.6 — Honest fix of the root comfy-kitchen pin miss (KREA2 RAM exhaustion)

This release fixes a **RAM exhaustion** bug on KREA2 fp8/int8 ConvRot checkpoints that v1.8.5 was supposed to fix but did not. v1.8.5 bumped the kitchen pin in the **wrong requirements file**; the Forge runtime kept installing an older kitchen and silently dequantized quantized weights to bf16, using up to ~64 GB of RAM.

---

## 1. Summary

| Item | Detail |
|---|---|
| Primary change | Bump the **root** `requirements.txt` pin to **`comfy-kitchen>=0.2.22`** |
| Why | v1.8.5 only raised the pin in **`ComfyUI-master/requirements.txt`**, but Forge installs from the **root** `requirements.txt`, which stayed at `>=0.2.21` |
| Symptom fixed | KREA2 (int8/fp8 ConvRot) checkpoints loaded and generated but consumed all ~64 GB RAM |
| Honest note | The intended v1.8.5 fix **never took effect** in the runtime; this release is the real correction |
| User action | Run **`pip install -U comfy-kitchen`** once (a plain `pip install -r requirements.txt` will not upgrade an already-satisfied `0.2.21`) |
| Unchanged | Issue #3 TE dequant fallback (v1.8.4); Anima RMS+RoPE fuse (v1.8.3); Krea2 depth ControlNet still unsupported |

---

## 2. Background

Forge installs its runtime dependencies from the **repository root** `requirements.txt`, not from `ComfyUI-master/requirements.txt`. v1.8.5 raised the kitchen pin only in the vendored `ComfyUI-master/requirements.txt`, so the runtime kept resolving `comfy-kitchen` to `0.2.21`.

`TensorCoreConvRotW4A4Layout` only exists in **comfy-kitchen >= 0.2.22**. With `0.2.21` installed, the grouped import in `ComfyUI-master/comfy/quant_ops.py:29` raises `ImportError: cannot import name 'TensorCoreConvRotW4A4Layout'`.

Because that import is a **single `try` block**, one missing name flips `_CK_AVAILABLE` to `False`, so `get_layout_class()` returns `None` for **every** quantized layer — not just ConvRot. The Issue #3 fallback (`backend/patch_comfy_quant_layout_fallback.py`, added in v1.8.3/v1.8.4) then converts all MixedPrecision weights to plain float Parameters: the ~12 GB int8/fp8 DiT becomes ~24 GB bf16. Combined with the fp16 TE, pinned shared memory, VAE, and Python/OS, total RAM exceeds 64 GB.

**The pip trap:** with `>=0.2.21` and `0.2.21` already installed, `pip install -r requirements.txt` reports "Requirement already satisfied" and never upgrades — so environments stayed broken even after pulling v1.8.5.

---

## 3. What changed

### 3.1 Root requirements pin

`requirements.txt:28`

```diff
- comfy-kitchen>=0.2.21
+ comfy-kitchen>=0.2.22
```

This forces the runtime environment to `0.2.22+`, so `TensorCoreConvRotW4A4Layout` imports cleanly, kitchen layouts register, quantized weights stay quantized in RAM, and the dequant fallback never fires.

### 3.2 Why v1.8.5 did not cover this

v1.8.5 intentionally left the root pin unchanged. The v1.8.4 dequant fallback had fixed the **crash** (`AttributeError: 'NoneType' object has no attribute 'Params'`), which masked the version gap: loading **succeeded**, but silently at ~2x RAM. This release corrects the pin in the file the runtime actually honors.

---

## 4. Install / update notes

1. `git pull` (or download) this release.
2. **Upgrade the kitchen explicitly** — pulling the repo alone does not change an already-satisfied venv:

```text
pip install -U comfy-kitchen
```

3. Restart Forge.
4. For native INT8 ConvRot checkpoints, prefer **Comfy-Org / ComfyUI-native** weights. **ComfyUI-INT8-Fast** dumps are a different format and need conversion before they load on the native path.

---

## 5. Out of scope

- Soft-import recovery for missing `TensorCoreConvRotW4A4Layout` without updating kitchen (optional hardening; not this release).
- Splitting the grouped `try` import in `quant_ops.py` so one missing name does not disable all layouts.
- Krea2 **depth ControlNet**.
- Creating or supporting ComfyUI-INT8-Fast–only weight formats inside Forge.

## 7. Verification checklist

1. `pip show comfy-kitchen` reports **`0.2.22`** or newer.
2. Startup no longer logs `cannot import name 'TensorCoreConvRotW4A4Layout'` from `comfy_kitchen`.
3. No `[Forge] comfy_kitchen layout missing ... dequantizing` messages appear during KREA2 model load.
4. KREA2 int8/fp8 ConvRot checkpoints load with **quantized** RAM usage (no ~2x bf16 blow-up); total RAM stays well under 64 GB.
5. v1.8.4 quantized TE fallback and v1.8.3 Anima fuse still behave as before.
