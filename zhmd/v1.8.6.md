# 版本 1.8.6 — 诚实修复 root comfy-kitchen 版本锁定的遗漏（KREA2 内存耗尽）

本次发布修复了 KREA2 fp8/int8 ConvRot 检查点上的 **内存耗尽** 问题——这个问题本应在 v1.8.5 中被修复，但实际上并没有。v1.8.5 在 **错误的 requirements 文件** 中提升了 kitchen 版本锁定；Forge 运行时仍然安装旧版 kitchen，并静默地将量化权重反量化为 bf16，最多占用约 64 GB 内存。

---

## 1. 概述

| 项目 | 详情 |
|---|---|
| 主要改动 | 将 **root** `requirements.txt` 的锁定提升为 **`comfy-kitchen>=0.2.22`** |
| 原因 | v1.8.5 只在 **`ComfyUI-master/requirements.txt`** 中提升了锁定，但 Forge 是从 **root** `requirements.txt` 安装的，而它仍停留在 `>=0.2.21` |
| 修复的症状 | KREA2（int8/fp8 ConvRot）检查点可以加载并生成，但会耗尽全部约 64 GB 内存 |
| 诚实说明 | v1.8.5 意图中的修复在运行时 **从未生效**；本次发布才是真正的修正 |
| 用户操作 | 执行一次 **`pip install -U comfy-kitchen`**（普通的 `pip install -r requirements.txt` 不会升级已满足的 `0.2.21`） |
| 未改动 | Issue #3 TE 反量化回退（v1.8.4）；Anima RMS+RoPE 融合（v1.8.3）；Krea2 depth ControlNet 仍不支持 |

---

## 2. 背景

Forge 从 **仓库根目录** 的 `requirements.txt` 安装运行时依赖，而不是从 `ComfyUI-master/requirements.txt`。v1.8.5 只在内置的 `ComfyUI-master/requirements.txt` 中提升了 kitchen 锁定，因此运行时仍然把 `comfy-kitchen` 解析为 `0.2.21`。

`TensorCoreConvRotW4A4Layout` 只存在于 **comfy-kitchen >= 0.2.22**。当安装的是 `0.2.21` 时，`ComfyUI-master/comfy/quant_ops.py:29` 中的分组 import 会抛出 `ImportError: cannot import name 'TensorCoreConvRotW4A4Layout'`。

由于该 import 是一个 **单一的 `try` 块**，一个缺失的名称就会把 `_CK_AVAILABLE` 翻转为 `False`，于是 `get_layout_class()` 对 **所有** 量化层都返回 `None`——而不仅仅是 ConvRot。随后 Issue #3 的回退逻辑（`backend/patch_comfy_quant_layout_fallback.py`，于 v1.8.3/v1.8.4 加入）会把所有 MixedPrecision 权重转换为普通 float 参数：约 12 GB 的 int8/fp8 DiT 变成约 24 GB 的 bf16。加上 fp16 TE、固定的共享内存、VAE 以及 Python/OS，总内存超过 64 GB。

**pip 陷阱：** 当锁定为 `>=0.2.21` 且已安装 `0.2.21` 时，`pip install -r requirements.txt` 会报告 “Requirement already satisfied” 而从不升级——因此即使拉取了 v1.8.5，环境仍然处于损坏状态。

---

## 3. 改动内容

### 3.1 Root requirements 锁定

`requirements.txt:28`

```diff
- comfy-kitchen>=0.2.21
+ comfy-kitchen>=0.2.22
```

这会强制运行时环境使用 `0.2.22+`，于是 `TensorCoreConvRotW4A4Layout` 可以正常 import、kitchen 布局得以注册、量化权重在内存中保持量化状态，反量化回退也不会触发。

### 3.2 为什么 v1.8.5 没有覆盖到这个问题

v1.8.5 有意保持 root 锁定不变。v1.8.4 的反量化回退已经修复了 **崩溃**（`AttributeError: 'NoneType' object has no attribute 'Params'`），这掩盖了版本差距：加载 **成功** 了，但静默地以约 2 倍内存运行。本次发布在运行时真正读取的那个文件里修正了锁定。

## 4. 安装 / 更新说明

1. `git pull`（或下载）本次发布。
2. **显式升级 kitchen** —— 仅拉取仓库不会改变一个已满足的 venv：

```text
pip install -U comfy-kitchen
```

3. 重启 Forge。
4. 对于原生 INT8 ConvRot 检查点，优先使用 **Comfy-Org / ComfyUI-native** 权重。**ComfyUI-INT8-Fast** 导出的是另一种格式，在原生路径加载前需要先转换。

---

## 5. 不在本次范围内

- 在不更新 kitchen 的情况下对缺失的 `TensorCoreConvRotW4A4Layout` 做软 import 恢复（可选加固；不在本次发布内）。
- 拆分 `quant_ops.py` 中分组的 `try` import，使单个缺失名称不再禁用所有布局。
- Krea2 **depth ControlNet**。
- 在 Forge 内创建或支持仅限 ComfyUI-INT8-Fast 的权重格式。

1. `pip show comfy-kitchen` 报告 **`0.2.22`** 或更新版本。
