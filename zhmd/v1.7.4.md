# Pony SDXL LoRA — CLIP 键映射修复

**产品：** Stable Diffusion WebUI Forge — Nunchaku  
**范围：** Pony / SDXL LoRA 在 IntegratedCLIP（Transformers 5.6+）下的 **CLIP-L（`lora_te1_*`）** 键绑定。  
**不在范围内：** UNet 键映射逻辑变更、Pony 专用 loader。

## 1. 摘要

Forge Classic Neo 在 IntegratedCLIP 下，CLIP 权重路径为 `clip_l.transformer.encoder.layers.*`（无 `text_model` 段）。  
旧版 `model_lora_keys_clip()` 仅查找 `transformer.text_model.encoder.layers.*`，导致 Pony / SDXL LoRA 的 **`lora_te1_*`（CLIP-L）** 几乎无法匹配。

**修复：** 在 `modules_forge/packages/comfy/lora.py` 的 `model_lora_keys_clip()` 中，对每层同时尝试两种相对路径（`text_model.encoder` 与 `encoder.layers`），使 `lora_te1_*` 正确映射到 IntegratedCLIP 的 state_dict 键。

**Git：** `08e6e70`（合并 PR #1 `3a8ea0c` / `3d1950d` 及本地 Pony 修复）。

---

## 2. 症状

使用 Pony 系 SDXL checkpoint + Pony LoRA 时可能出现：

| 现象 | 说明 |
|------|------|
| 仅 UNet 生效 | 画面风格变化，但 prompt 相关 LoRA 效果弱或无效 |
| CLIP 完全无效 | `lora_te1_*` 未绑定到任何模型键 |
| 整包 LoRA 被拒绝 | 日志 `[LORA] LoRA mismatch for ...`，CLIP 未匹配比例超过 50% 门限 |

典型日志（修复前）：

```
[LORA] Loading <file>.safetensors for UNet with 0 unmatched keys
[LORA] LoRA mismatch for CLIP: <file>.safetensors
```

## 3. 根本原因

### 3.1 IntegratedCLIP 与旧路径

| 组件 | Transformers 4.x–5.5 | Transformers 5.6+ / IntegratedCLIP |
|------|----------------------|--------------------------------------|
| CLIP-L 层权重 | `clip_l.transformer.**text_model**.encoder.layers.*` | `clip_l.transformer.**encoder**.layers.*` |

Forge `backend/loader.py` 在加载 IntegratedCLIP 时会规范化键名；**运行时 state_dict 使用 `encoder.layers` 布局**。

### 3.2 LoRA 文件侧键名（不变）

Pony / SDXL LoRA 仍使用 A1111 / Comfy 惯例，例如：

- `lora_te1_text_model_encoder_layers_0_self_attn_k_proj`
- `lora_unet_*`（UNet 部分通常仍能匹配）

问题集中在 **CLIP-L 的 `lora_te1_*` → 模型键** 映射。

---

## 4. 修复内容

**文件：** `modules_forge/packages/comfy/lora.py`  
**函数：** `model_lora_keys_clip()`

对 `clip_h` / `clip_l` / `clip_g` 的每一 encoder 层，按顺序尝试：

```python
clip_layer_paths = (
    "transformer.text_model.encoder.layers.{}.{}.weight",
    "transformer.encoder.layers.{}.{}.weight",
)
```

若键存在于 `model.state_dict()`，则注册多种 LoRA 别名，包括：

- `lora_te1_text_model_encoder_layers_{block}_{layer}`（SDXL / Pony 标准）
- `text_encoder.text_model.encoder.layers.{block}.{layer}`（diffusers 格式）
- `lora_te2_*`（存在 `clip_g` 时的 SDXL 双文本编码器）

IntegratedCLIP 上通常 **第一条路径未命中、第二条命中**，从而 `lora_te1_*` 可正确加载。

## 5. 50% 匹配门限

**文件：** `extensions-builtin/sd_forge_lora/networks.py`

```python
if _unmatches / len(lora) > 0.5:
    print(f"[LORA] LoRA mismatch for {model_flag}: {filename}")
    return model, clip
```

当 CLIP 侧几乎全部未匹配时，即使 UNet 键可匹配，**整个 LoRA 文件也会被跳过**。本修复通过提高 CLIP 匹配率，避免「看起来像 LoRA 完全无效」的情况。

---

## 6. 验证建议

1. 使用 Pony SDXL checkpoint 加载含 `lora_te1_*` 的 LoRA。
2. 确认日志为 `Loading ... for CLIP with 0 unmatched keys`（或少量 unmatched），而非 `LoRA mismatch for CLIP`。
3. 对比同一 prompt：修复后应能观察到 **文本侧 LoRA** 对画面的影响。

英文技术说明：`docs/Pony_SDXL_LoRA_CLIP_Fix.md`
