# Version 1.8.5 — ComfyUI-master sync and comfy-kitchen bump

This release pushes the **vendored `ComfyUI-master` tree** and the **kitchen pin** that remote users need for current Comfy quantization layouts (including INT8 ConvRot / `TensorCoreConvRotW4A4Layout`). Forge still installs runtime deps from the **repository root** `requirements.txt`.

---

## 1. Summary

| Item | Detail |
|---|---|
| Primary change | Sync vendored **`ComfyUI-master`** to the latest upstream tree used for Forge imports |
| Kitchen (vendored tree) | **`comfy-kitchen==0.2.22`** in `ComfyUI-master/requirements.txt` |
| Kitchen (Forge runtime) | Root **`requirements.txt`** keeps **`comfy-kitchen>=0.2.21`** (unchanged; this is what Forge `pip install -r` uses) |
| Why | Older remote trees / kitchens can fail with `cannot import name 'TensorCoreConvRotW4A4Layout'` and disable FP8/INT8 kitchen paths |
| Unchanged | Issue #3 TE dequant fallback (v1.8.4); Anima RMS+RoPE fuse (v1.8.3); Krea2 depth ControlNet still unsupported |

---

## 2. Background

Forge embeds a **`ComfyUI-master/`** copy for model / quant / ops imports. Local development had already moved to a newer master + kitchen, while **`origin/main`** lagged. Users who pull only the published tree can therefore miss:

- Newer `ComfyUI-master` modules (JoyImage, Anima LLLite, API nodes, detection updates, tests, …)
- A kitchen version that exports **`TensorCoreConvRotW4A4Layout`**

`comfy/quant_ops.py` imports that symbol together with INT8/FP8 layouts. If the installed kitchen is too old, the **entire** kitchen import fails and quantized paths degrade.

---

## 3. What changed

### 3.1 Vendored `ComfyUI-master`

Synced the vendored tree used for Forge imports, including (non-exhaustive):

- JoyImage model / TE / nodes
- Anima LLLite
- HeyGen / Sync.so API nodes
- Model detection, supported models, attention / cosmos predict2 updates
- Unit / execution test updates
- `ComfyUI-master/requirements.txt` → **`comfy-kitchen==0.2.22`**

### 3.2 Forge root requirements

Root `requirements.txt` already ships **`comfy-kitchen>=0.2.21`**. That pin is what Forge applies on install/update. After pulling v1.8.5, re-run:

```text
pip install -r requirements.txt
```

so the active venv actually has a kitchen that provides current layouts.

---

## 4. Install / update notes

1. `git pull` (or download) this release.
2. **`pip install -r requirements.txt`** from the Forge root (not `ComfyUI-master/requirements.txt`).
3. Restart Forge.
4. For native INT8 ConvRot checkpoints, prefer **Comfy-Org / ComfyUI-native** weights. **ComfyUI-INT8-Fast** dumps are a different format and need conversion before they load on the native path.

---

## 5. Out of scope

- Soft-import recovery for missing `TensorCoreConvRotW4A4Layout` without updating kitchen (optional hardening; not this release).
- Silent checkpoint→LoRA fallback hardening.
- Krea2 **depth ControlNet**.
- Creating or supporting ComfyUI-INT8-Fast–only weight formats inside Forge.

## 7. Verification checklist

1. After pull: `pip show comfy-kitchen` shows a version that satisfies **`>=0.2.21`** (ideally **0.2.22+**).
2. Startup no longer logs `cannot import name 'TensorCoreConvRotW4A4Layout'` from `comfy_kitchen.tensor`.
3. Native INT8 ConvRot / MixedPrecision checkpoints that worked on an updated local tree also load on a fresh clone of this release.
4. v1.8.4 quantized TE fallback and v1.8.3 Anima fuse still behave as before.
