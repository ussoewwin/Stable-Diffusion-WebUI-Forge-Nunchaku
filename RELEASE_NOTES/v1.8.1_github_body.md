# Version 1.8.1 — Nunchaku SDXL code removal (phase 1)

This release is a **maintenance / cleanup** release. It removes the dead Nunchaku SDXL implementation that is no longer used, while guaranteeing **no behavioral change** to normal SDXL, fp16 / fp8 / int8, or Nunchaku for other models (Flux1, Qwen Image, Z-Image / ZIT).

There are **no new features** and **no user-facing UI changes** in this release.

---

## 1. Why this cleanup

The Nunchaku SDXL path (`SVDQUNet2DConditionModel` and its dedicated CLIP converter) was an early experiment that is no longer part of the supported model set. It left behind:

- Dedicated modules that were only imported by their own callers.
- SDXL-specific branches scattered across the loader, the LoRA network layer, and the RES4LYF beta samplers.
- Orphaned / duplicate files.

Keeping this dead code increased the risk of accidental regressions and made the Nunchaku code paths (Flux1 / Qwen Image / Z-Image) harder to read. Phase 1 removes it surgically.

---

## 2. Files deleted

| File | Lines removed | Role |
|---|---|---|
| **`backend/nn/nunchaku_sdxl_unet.py`** | 2447 | Defined `SVDQUNet2DConditionModel` (Nunchaku SDXL UNet) and all SDXL-specific LoRA mapping / key-conversion / QKV-fusion logic. |
| **`backend/nn/nunchaku_sdxl_clip.py`** | 359 | Dedicated Nunchaku SDXL CLIP → Forge format converter (`convert_nunchaku_clip_to_forge_format`). |
| **`backend/nn/nunchaku_sdxl_unet_append.py`** | 48 | Orphaned duplicate `SVDQUNet2DConditionModel` / `patch_nunchaku_sdxl` (no live callers). |

All three files were only reachable through the SDXL-specific branches removed in Section 3, so deleting them cannot affect any other model.

---

## 3. Surgical edits (SDXL-only branches removed)

### 3.1 `backend/loader.py`

**UNet dispatch** — the `nunchaku` special case for `UNet2DConditionModel` was removed, so SDXL UNets always take the standard integrated path:

```python
if cls_name == "UNet2DConditionModel":
    model_loader = lambda c: IntegratedUNet2DConditionModel.from_config(c)
```

(Previously this branched into `SVDQUNet2DConditionModel(c)` when `guess.nunchaku` was set.)

**CLIP conversion** — the entire Nunchaku-SDXL CLIP conversion block (the `should_convert` / `SDXL` type sniffing that called `convert_nunchaku_clip_to_forge_format`) was removed from `forge_loader`. Flux and Qwen CLIP were explicitly forbidden inside that block, so their behavior is unchanged.

> Note: the INT8 loader branch (`int8_tensorwise`) and the Flux / Qwen / Z-Image Transformer dispatch are **untouched**.

### 3.2 `extensions-builtin/sd_forge_lora/networks.py`

Removed two SDXL-only LoRA blocks that were gated on `isinstance(..., SVDQUNet2DConditionModel)`:

- The **add** block in `load_lora_for_models` (appended to `diffusion_model.loras`).
- The **clear** block in `load_networks`.

The ZIT (`NextDiT`), Nunchaku Qwen Image, Flux1, and standard FP LoRA paths are left exactly as they were.

### 3.3 RES4LYF beta samplers

The four samplers each carried an `is_nunchaku_sdxl` flag used only for a debug/label string (`model_type_str = "Nunchaku SDXL"`). The flag declaration, the `SVDQUNet2DConditionModel` import, the `isinstance` branch, and every `elif is_nunchaku_sdxl:` label branch were removed:

- `modules/RES4LYF/beta/rk_sampler_beta.py`
- `modules/RES4LYF/beta/rk_method_beta.py`
- `modules/RES4LYF/beta/rk_guide_func_beta.py`
- `modules/RES4LYF/beta/rk_noise_sampler_beta.py`

The `Nunchaku QwenImage`, `Nunchaku FLUX1`, `SDXL`, and `FLUX1` detection labels remain intact, so sampler behavior for every supported model is identical.

---

## 4. Impact analysis (no regressions)

- **Normal SDXL / fp16 / fp8 / int8** — the standard `IntegratedUNet2DConditionModel` path is now the only path for `UNet2DConditionModel`; the INT8 (`int8_tensorwise`) early-return branch is untouched.
- **Nunchaku Flux1 / Qwen Image / Z-Image** — their Transformer classes live in `backend/nn/svdq.py` (and `_qwen_lora.py` / `_zimage_lora.py`), none of which reference the deleted SDXL files. All deleted branches were guarded to explicitly exclude these models.
- **LoRA** — SDXL, Flux1, Qwen Image, and Z-Image LoRA paths are unchanged; only the dead SDXL-Nunchaku LoRA add/clear branches were removed.
- **`modules/ComfyUI-nunchaku-unofficial-loader/`** — out of scope, not touched.
